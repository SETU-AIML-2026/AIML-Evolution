# Submitting This Lab

You submit **your Sections 1 to 7 work, as one zip**, to a OneDrive folder, exactly as in previous weeks.

## The three steps

### 1. Answer as you go

Download **Week 07 Submission Kit** from this unit and unzip it into your `week07-lab` folder, beside `UCI_Credit_Card.csv` and `w7lab.py`. It holds three files:

| File | What it is |
|---|---|
| `SUBMISSION.md` | Your answers, one part per lab section |
| `make_submission.py` | Builds the zip |
| `setup_check.py` | Environment report |

Open `SUBMISSION.md` and fill in each section as you finish it. Most of the questions are the ones in the lab text, so this is a transcription job, as long as you do it at the time.

Keep your code in the lab folder as you write it: `mlp.py`, `section1_dials.py` to `section6_credit.py`, and your `exercise_7_*.py` files (or one notebook if you prefer). Save the two pictures, `section2_line.png` and `section6_moons.png`, and any curves you draw for Section 7. They all go in automatically. Your fixed `broken_run.py` goes in too.

### 2. Build your submission

In the lab folder, with your virtual environment active:

```bash
python make_submission.py
```

It asks for your student number the first time and remembers it afterwards. It checks that `SUBMISSION.md` has no `TODO` left, runs `setup_check.py`, gathers your files, and writes one zip named after you. The provided `UCI_Credit_Card.csv` and `w7lab.py` are left out.

### 3. Upload it

Upload that one zip to the Week 7 OneDrive folder on the course site.

## When it stops

- **"SUBMISSION.md still has TODO markers"**: finish those answers, or run `python make_submission.py --force` to submit it marked incomplete.
- **It picks the wrong week**: run `python make_submission.py --week 7`.
- **Want to see what would go in first**: run `python make_submission.py --dry-run`.

Both scripts run entirely on your machine. Nothing is uploaded by them; they only read this folder and write one zip into it.
