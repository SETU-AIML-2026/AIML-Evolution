# Step 4 · Four fixes, and what each one costs

*≈ 20 min · lecture: "fairness is not a feature you add; it is a set of choices you already made"*

## What you are doing

Now try to close the gap. Four ideas from the lecture, one table:

1. **Drop the proxy column** (`postcode_score`): remove the leak.
2. **Reweight the training data** so group B counts as much as group A.
3. **Different thresholds per group**: tune the line separately for A and B until one gap is zero.
4. **Fix the labels**: go back to pipeline stage *Labels* and use the correct repayment records.

## Run this (about 20 seconds)

## What you should see

| strategy | accuracy | selection_gap | tpr_gap | fpr_gap | ppv_gap | |
|---|---|---|---|---|---|---|
| baseline (nothing done) | 0.699 | 0.203 | 0.205 | 0.122 | 0.079 | |
| drop postcode_score | 0.684 | **0.273** | 0.273 | 0.202 | 0.046 | ← worse |
| reweighting (pre) | 0.682 | 0.103 | 0.115 | 0.020 | 0.126 | |
| per-group thresholds (selection_gap) | 0.684 | **0.000** | 0.030 | 0.098 | **0.163** | ← one gap zero, another up |
| per-group thresholds (fpr_gap) | 0.689 | 0.085 | 0.094 | 0.001 | 0.130 | |
| fix the label (stage 3) | 0.698 | **0.033** | 0.033 | 0.032 | 0.009 | ← best, and no accuracy lost |

`selection_gap` is the approval-rate gap from Step 3. Read the table top to bottom:

- Dropping the proxy makes the gap **bigger**. The model leans harder on the other leaky columns.
- Reweighting helps a bit and costs a bit of accuracy.
- Per-group thresholds zero the gap you tuned for and **push another gap up**. You cannot
  have every gap at zero at once; the lecture called this the impossibility result.
- **Fixing the label** removes nearly all of it and costs almost nothing, because that is
  **where the harm was put in**. The cheapest real fix is the earliest one.
