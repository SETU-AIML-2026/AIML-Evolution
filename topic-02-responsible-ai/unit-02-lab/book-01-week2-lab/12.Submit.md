# Submitting This Lab

Your submission is **one file**. A script in the lab folder builds it for you.

It works exactly as it did in Week 1, and will for the rest of the semester.

## The three steps

### 1. Answer the questions, and write the model card

Open `SUBMISSION.md` in the lab folder. Fill in your student number, your name,
and the answers to this week's exercises. Delete each `TODO` marker as you
finish that section.

Then make the model card, which is this week's graded deliverable:

```bash
cp model_card_template.md model_card.md
```

Fill it in. The fairness criterion, the reasoning, and the cost in numbers are
the marked parts.

### 2. Build your submission

In the lab folder, with your virtual environment active:

```bash
python make_submission.py
```

It will ask for your student number the first time and remember it afterwards.

The script checks your work, runs `setup_check.py`, gathers your files, and
produces a single zip named after you:

```
submission-week02-20012345.zip
```

It tells you exactly where that file is when it finishes.

**If it stops instead**, read the message. It stops for two reasons only: your
`SUBMISSION.md` still has `TODO` markers in it, or `model_card.md` does not
exist. Finish the one it names and run the script again.

### 3. Upload it

**[Upload your Week 2 submission here](REPLACE-WITH-WEEK-2-FORM-LINK)**

**[Submission Option 2](REPLACE-WITH-WEEK-2-SHAREPOINT-LINK)**

Upload that one zip. Nothing else. Do not upload individual files, do not email
them, and do not upload a folder.

That is the whole submission.

## What is in the file

You can open the zip and look — there are no surprises in it:

| Inside the zip | What it is |
|---|---|
| `SUBMISSION.md` | Your answers |
| `model_card.md` | Your graded deliverable |
| `datasheet.md` | If you wrote one |
| Any images you saved | Your plots |
| `submission/` | Anything else you chose to include |
| `setup_check_output.txt` | Your environment report, captured automatically |
| `manifest.json` | Your student number, the week, and a timestamp |

Nothing is sent anywhere. The script runs entirely on your machine and only
writes a file.

## Common problems

**"It says my SUBMISSION.md is not finished."**
There is still a `TODO` in it. Search for the word and answer that section.

**"It says model_card.md is missing."**
Copy the template: `cp model_card_template.md model_card.md`, then fill it in.

**"My plot disappeared."**
You saved it in `figures/`. That folder is in `.gitignore` and `run_lab.py`
overwrites it. Save submission plots in the lab folder root instead.

**"I need to submit even though it is incomplete."**
You can, and sometimes that is the right call:

```bash
python make_submission.py --force
```

It will be recorded as incomplete, which is better than not being recorded
at all.

**"It could not work out which week this is."**
Tell it:

```bash
python make_submission.py --week 2
```

**"I typed my student number wrong."**
Delete the file `.student_number` in the lab folder and run the script again.

**"I already uploaded and then fixed something."**
Upload again. The latest upload is the one that counts.

## Anything else to add

If you want to include extra work — a notebook, some notes, a second plot —
make a folder called `submission` inside the lab folder and put them there.
Everything in it goes into the zip.

## Deadlines and marks

Weekly labs are **pass/fail completion checkpoints**. No single one carries a
mark. They exist so that you and I both know, every week, whether you are
keeping up.

Deadlines are **23:59 on the Sunday after each lab**. Late still counts as
submitted; it is simply recorded as late.

The Week 6 quiz and the Week 12 project are submitted separately and are the
things that carry marks. This week's model card is practice for the second of
those, in the exact format it will take.

## If you are stuck

There are no lab tutors on this module, so the order matters.

1. **The troubleshooting table on the previous page.** Ten problems, and between
   them they cover most of what actually goes wrong in this lab.
2. **The module channel.** Post there rather than emailing me — someone else has
   the same problem, and the answer helps everyone reading. Include the output of
   `python setup_check.py`, not "it doesn't work".
3. **Email me.** Expect a reply within two working days.

Getting stuck on setup is completely normal and says nothing about your ability.
Getting stuck silently for three weeks is the only version that causes real
damage.
